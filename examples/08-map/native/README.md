# ZeMap on a phone — Expo, React Native, no native build of our own

The same service, the same queries and the same shared route row as `../flutter` and
`../web`, through **zb-client-ts**. Nothing of ours is cross-compiled: no Zig, no NDK,
no `.xcframework`. That is the whole reason this app exists (NOTES §10ih).

## Why not the Flutter app

The TypeScript client needs nothing from this app but its options: zb-client-ts's
react-native entry — picked by Metro through the `react-native` export condition —
brings the storage (expo-sqlite), zstd (fzstd, or libzb's native decoder when the app
has the ZbNative module, as 06-large-table/react-native does), and the crypto Hermes
lacks (`crypto.randomUUID`, `crypto.subtle.digest`). The app installs the two native
packages that entry needs, `expo-sqlite` and `react-native-get-random-values`.

## Run it

Expo Go will not work: MapLibre is native, so this needs a **development build**.

    # the dev stack first: PostgreSQL, nats-server, the bridge, and the map service
    scripts/native/up.sh
    examples/08-map/poi_service.py --label hub

    pnpm install --ignore-workspace
    EXPO_PUBLIC_CREDS="$(cat ../../../scripts/native/creds/omar.creds)" \
    EXPO_PUBLIC_NATS_URL=ws://127.0.0.1:8080 \
      pnpm ios          # or: pnpm android

⚠️ **`ws://`, not `nats://`.** This client speaks NATS over WebSocket; the server's
`websocket` block is already on port 8080 with `no_tls` (scripts/native/nats-server-jwt.conf).

⚠️ **`127.0.0.1` reaches the host from the iOS SIMULATOR only.** A real device needs the
Mac's LAN address, and the Android emulator's alias for the host is `10.0.2.2`.

⚠️ **The creds are an app secret, never a repo path.** Both Flutter apps still read them
from the developer's home directory, which no app bundle can do. Here they arrive as
`EXPO_PUBLIC_CREDS`; a shipped app would enrol and store its own.

`ios/` and `android/` are generated by `expo prebuild` from `app.json` and are
git-ignored — build output, not source.

## Android

The build uses Android Studio's **SDK**, **emulator** and whatever **AVD** you created in
it — but not the IDE. `expo run:android` drives the same Gradle build Studio would, from
the command line, which is scriptable and shows its errors in the terminal.

⚠️ **It needs JDK 17, and Studio's bundled JDK is not it.** Gradle refuses anything newer
with `Unsupported class file major version 69` — subtract 44 and that is Java 25, which
is what Android Studio bundles and what Homebrew installs by default. React Native 0.76
wants 17:

    brew install openjdk@17     # keg-only: it sits BESIDE your other JDKs

    export ANDROID_HOME="$HOME/Library/Android/sdk"
    export JAVA_HOME="/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home"
    export PATH="$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH"

    emulator -avd <your-avd> &
    npx expo run:android

**If you prefer Android Studio**, open `android/` and point its Gradle JDK at 17 first —
Settings → Build, Execution, Deployment → Build Tools → Gradle → *Gradle JDK*. Left at
its default it uses the bundled 25 and fails exactly as above. The IDE is worth opening
for Logcat, native crash traces, the layout inspector and profiling; the build itself
does not need it.

⚠️ **The host address differs from iOS and is decided in code, not configuration.** The
iOS simulator shares the Mac's network stack, so `127.0.0.1` is the Mac. The Android
emulator sits behind its own NAT and reserves `10.0.2.2` for the host — `127.0.0.1` there
is the emulator. `src/client.ts` picks by `Platform.OS`, so ONE bundler serves both. Do
NOT set `EXPO_PUBLIC_NATS_URL` unless you mean to override it, because it is inlined at
bundle time and whatever you pass wins on every platform (§10io). A real device on your
network is exactly when to set it, to the Mac's LAN address.

First build here: 3m 59s, 300 Gradle tasks.

## What it draws

OpenStreetMap raster, the same as `../web` and the same as the Flutter app's fallback.
No account, no API key. MapLibre can read the R2 vector archive the Flutter app uses,
which is the upgrade when this app has a style sheet of its own.

The markers are the ANSWER and are never stored (§10ic): what is on screen is what was
just asked for. `charge_points` stays DECLARED on-demand so a mutation has its
descriptor, and the only charge point this phone would store is one it wrote itself.
