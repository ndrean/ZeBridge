# ZeMap on a phone — Expo, React Native, libzb

The same service, the same queries and the same shared route row as `../flutter` and
`../web`, through **libzb**, the C client, behind zb-react-native's Expo module. The app
passes its options (`src/client.ts`); libzb keeps the replica in its own SQLite, speaks
NATS over TCP and merges the route's registers with the same rule as every other client.

## Run it

Expo Go will not work: MapLibre and libzb are native, so this needs a **development build**.
The map services (`chargers_near`, `fuel_near`) must answer on the bridge's NATS
(`examples/08-map/poi_service.py`), and its PostgreSQL must hold `routes` and
`charge_points`.

    ../../../zb-react-native/scripts/build-ios.sh       # libzb for the module (iOS)
    ../../../zb-react-native/scripts/build-android.sh   # libzb for the module (Android)

    pnpm install --ignore-workspace
    pnpm prebuild
    EXPO_PUBLIC_ZB_INVITE=<code> pnpm ios          # or: pnpm android

The module carries a COPY of libzb: after any libzb change, run the build script again
and rebuild the app.

The settings, read at build time (clear Metro's cache after changing one):

* `EXPO_PUBLIC_ZB_INVITE`: the invite, for the first run. libzb keeps the identity beside
  the replica afterwards, so later builds need none.
* `EXPO_PUBLIC_ZB_BRIDGE_URL`: the bridge, `https://bridge.zebridge.eu` by default.
* `EXPO_PUBLIC_ZB_NATS_URL`: another NATS address than the one the bridge names, such as a
  leaf. The replica and identity are kept per bridge and NATS host, so a new address needs
  its own invite.

An invite is a row the backend writes:

```sql
INSERT INTO zebridge_invites (principal, tenant_id)
VALUES ('<principal>', '<tenant>')
RETURNING code;
```

`ios/` and `android/` are generated by `expo prebuild` from `app.json` and are
git-ignored — build output, not source.

## Android

The build uses Android Studio's **SDK**, **emulator** and whatever **AVD** you created in
it — but not the IDE. `expo run:android` drives the same Gradle build Studio would, from
the command line, which is scriptable and shows its errors in the terminal.

⚠️ **It needs JDK 17, and Studio's bundled JDK is not it.** Gradle refuses anything newer
with `Unsupported class file major version 69` — subtract 44 and that is Java 25, which
is what Android Studio bundles and what Homebrew installs by default. The builds here
(React Native 0.86) are tested with 17:

    brew install openjdk@17     # keg-only: it sits BESIDE your other JDKs

    export ANDROID_HOME="$HOME/Library/Android/sdk"
    export JAVA_HOME="/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home"
    export PATH="$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH"

    emulator -avd <your-avd> &
    npx expo run:android

**If you prefer Android Studio**, open `android/` and point its Gradle JDK at 17 first —
Settings → Build, Execution, Deployment → Build Tools → Gradle → *Gradle JDK*. Left at
its default it uses the bundled 25 and fails exactly as above. The IDE is worth opening
for Logcat, native crash traces, the layout inspector and profiling; the build itself
does not need it.

First build here: 3m 59s, 300 Gradle tasks.

## What it draws

OpenStreetMap raster, the same as `../web` and the same as the Flutter app's fallback.
No account, no API key. MapLibre can read the R2 vector archive the Flutter app uses,
which is the upgrade when this app has a style sheet of its own.

The markers are the ANSWER and are never stored: what is on screen is what was
just asked for. `charge_points` stays DECLARED on-demand so a mutation has its
descriptor, and the only charge point this phone would store is one it wrote itself.
